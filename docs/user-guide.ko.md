# ragkit 사용자 가이드

ragkit은 문서를 기반으로 답하는 에이전트를 만들고 운영하는 멀티 에이전트 RAG 플랫폼입니다. 관리자 UI(http://localhost:5173)에서 모든 기능을 사용합니다.

## 1. 기본 개념

| 개념 | 설명 |
| ---- | ---- |
| **Workspace** | 멤버·권한과 문서를 소유하는 단위입니다. 워크스페이스 안에 에이전트를 여러 개 둘 수 있습니다. |
| **Agent** | 대화 상대입니다. 에이전트마다 모델, 검색 파이프라인, 라우터, 위임 대상, 검색할 문서 세트를 따로 설정합니다. 대화 기록·프롬프트·평가·피드백은 에이전트에 속합니다. |
| **Document Set** | 워크스페이스 문서를 이름 붙여 묶은 것입니다. 한 문서가 여러 세트에 들어갈 수 있습니다. |

에이전트는 고른 세트에 든 문서만 검색합니다. 세트를 하나도 고르지 않으면 아무 문서도 검색하지 않고 모델 지식만으로 답합니다. 새로 업로드한 문서는 세트에 넣어야 에이전트가 검색합니다.

## 2. 로그인과 워크스페이스 선택

관리자로부터 받은 이메일과 비밀번호로 로그인합니다. 사이드바 상단의 드롭다운에서 작업할 워크스페이스를 고르세요. 선택한 워크스페이스와 에이전트는 브라우저에 저장되어 다음 접속 때도 유지됩니다.

> 드롭다운에 워크스페이스가 보이지 않으면 superadmin에게 워크스페이스 생성이나 멤버 초대를 요청하세요.

## 3. Agents — 에이전트 고르기·만들기

첫 화면에 현재 워크스페이스의 에이전트가 카드로 표시됩니다. 카드에는 모델, 검색 가능한 문서 수, 라우트 수, 시작 질문이 보입니다.

- **Start chat** 또는 시작 질문을 누르면 그 에이전트와 대화를 시작합니다.
- **Configure**는 Agent Settings로 이동합니다 (워크스페이스 admin).
- **New agent** 타일에서 이름을 입력해 새 에이전트를 만듭니다. **Start from**에서 기존 에이전트를 고르면 그 설정을 복사합니다. 다른 워크스페이스의 에이전트를 복사하면 문서 세트와 파이프라인 지정은 비워집니다.

## 4. Chat

- 헤더의 드롭다운에서 대화할 에이전트를 바꿀 수 있습니다.
- 왼쪽 목록은 이 에이전트와의 대화 기록입니다. 대화 제목은 첫 질문의 앞 40자로 정해집니다.
- 답변의 `[1]` 같은 인용에 마우스를 올리면 근거 구절이, 클릭하면 해당 문서가 열립니다.
- 오른쪽 패널의 **Graph** 탭은 실행 중인 노드를 따라 켜지고, **Trace** 탭은 실행 구간별 시간과 토큰을 보여줍니다.
- **Retrieval** 토글: Auto(라우터가 판단) / On(항상 검색) / Off(검색 안 함).
- 에이전트가 MCP 도구를 쓰면 답변 위에 호출 목록(도구, 인자, 상태)이 표시됩니다. 승인이 필요한 도구는 실행 전에 멈추고 **승인 카드**가 뜹니다. 자세한 내용은 [8장](#8-mcp-servers와-승인-워크스페이스-admin)을 보세요.
- 답변마다 👍/👎를 남길 수 있습니다. 👎를 받은 질문은 Evaluate에서 평가 세트로 가져올 수 있습니다.

## 5. Documents

### 업로드

**Documents** 페이지 상단의 Upload 폼을 사용합니다.

| 필드 | 설명 |
| ---- | ---- |
| Title | 문서를 식별할 이름 (필수) |
| File | 업로드할 파일 (필수) |
| Description | 문서에 대한 부가 설명 (선택) |
| Chunking Strategy | 텍스트 분할 방식 선택 (선택, 기본값: Recursive) |

**Upload** 버튼을 누르면 파일 저장 → 텍스트 추출 → 임베딩 → 벡터 저장까지 순서대로 처리됩니다. 완료되면 우상단에 성공 알림이 표시됩니다.

### 청킹 전략

문서마다 다른 청킹 전략을 지정할 수 있습니다.

| 전략 | 적합한 경우 |
| ---- | ----------- |
| Recursive (기본) | 대부분의 파일 형식에 범용으로 사용 |
| Markdown Header | `.md` 파일을 헤더(H1–H4) 단위로 분할할 때 |
| Character | 특정 구분자(예: `\n\n`) 기준으로 분할할 때 |
| Token (tiktoken) | LLM 컨텍스트 윈도우 기준으로 토큰 수를 제한할 때 |

어떤 전략이 적합한지 확인하려면 업로드 전에 **Retrieval Lab → Chunking** 탭에서 미리 테스트해 보세요.

> **업로드가 실패하는 경우**
> - 임베딩 서비스(Ollama)가 실행 중이지 않으면 오류 알림이 표시됩니다. Ollama를 먼저 실행한 뒤 다시 시도하세요.
> - 텍스트를 추출할 수 없는 파일(예: 스캔 이미지 PDF)은 업로드에 실패할 수 있습니다.

### 목록과 상태

업로드한 문서는 **Documents** 페이지 하단 목록에서 확인할 수 있습니다.

- 제목으로 필터링하려면 상단 검색창에 키워드를 입력하세요.
- **Status** 컬럼에서 인덱싱 상태를 확인할 수 있습니다. `indexed` 상태여야 검색에 사용됩니다.

### 상세와 관리

목록에서 문서 제목을 클릭하면 상세 페이지로 이동합니다.

#### 미리보기

**Preview** 버튼을 클릭하면 PDF 및 텍스트 파일을 브라우저에서 바로 확인할 수 있습니다.

#### 다운로드

**Download** 버튼으로 원본 파일을 내려받을 수 있습니다.

#### 파일 교체

새 파일로 교체하려면 **Replace file** 섹션에서 파일을 선택하고 **Replace and re-index** 버튼을 클릭하세요. 기존 벡터가 삭제되고 새 파일로 재인덱싱됩니다.

#### 삭제

**Delete** 버튼을 클릭하면 문서와 관련된 모든 데이터(파일, 벡터)가 삭제됩니다. 삭제는 되돌릴 수 없습니다.

## 6. Document Sets

문서를 묶어 에이전트별로 검색 범위를 나눌 때 사용합니다.

1. **+ New set**을 누르고 이름과 설명을 입력합니다.
2. 아래 목록에서 넣을 문서를 체크하고 **Create set**을 누릅니다.
3. Agent Settings의 **Document sets** 섹션에서 에이전트가 검색할 세트를 고릅니다.

목록의 각 세트에는 문서 수와 이 세트를 쓰는 에이전트가 표시됩니다.

> 에이전트가 사용 중인 세트는 삭제할 수 없습니다. 에이전트가 답할 수 있는 문서가 조용히 사라지지 않도록 하기 위해서입니다. 먼저 에이전트 설정에서 세트 선택을 해제하세요.

## 7. Agent Settings *(워크스페이스 admin)*

상단 드롭다운에서 설정할 에이전트를 고릅니다. 변경 내용은 **Save** 후 다음 메시지부터 적용됩니다.

| 섹션 | 설정 |
| ---- | ---- |
| Profile | 이름(**Rename**), 아이콘·색상, 설명, 시작 질문(최대 6개) |
| Model | LLM provider·모델·temperature. 비워 두면 `config.yaml` 기본값을 씁니다. API 키는 `.env`에만 둡니다. |
| Document sets | 이 에이전트가 검색할 세트. 하나도 고르지 않으면 아무 문서도 검색하지 않습니다(카드의 문서 수가 주황색 0으로 표시). |
| Retrieval | 검색 파이프라인(Retrieval Lab의 active 파이프라인), 검색 결과 수, 최대 tool 호출 횟수, 기본 검색 모드 |
| Delegation | 질문이 자기 문서 범위를 벗어날 때 tool처럼 호출할 다른 에이전트. 위임은 한 단계까지만 되고, 사용자가 직접 대화할 수 있는 에이전트에게만 위임됩니다. |
| MCP tools | 워크스페이스 MCP 서버의 도구 중 이 에이전트가 쓸 것과, 각 도구를 바로 실행(**Run**)할지 사용자 승인 후 실행(**Ask first**)할지. 읽기 전용 도구는 Run, 데이터를 바꾸는 도구는 Ask first가 기본값입니다. |
| Router | supervisor가 질문을 보낼 전문 에이전트(retrieval / summary / comparison / direct)의 사용 여부와 분류 기준 |
| Delete agent | 에이전트와 그 프롬프트·대화·평가·피드백을 삭제합니다. 워크스페이스 문서와 문서 세트는 남습니다. |

오른쪽 **Router preview**는 저장 전 설정으로 실제 실행될 그래프를 그립니다.

## 8. MCP Servers와 승인 *(워크스페이스 admin)*

에이전트가 문서 검색 외에 외부 시스템을 조회하거나 바꿀 수 있도록, 워크스페이스에 원격 MCP 서버를 등록합니다.

### 서버 등록

1. **+ Add server**를 누르고 이름과 URL(streamable HTTP, 예: `http://localhost:8765/mcp`)을 입력합니다.
2. 서버에 토큰이 필요하면 **Token variable**에 ragkit 서버의 환경변수 이름을 적습니다. 이름은 `MCP_TOKEN_`으로 시작해야 하며, 토큰 값은 `.env`에만 둡니다. 화면에는 변수가 설정됐는지(`set` / `not set`)만 표시됩니다.
3. **Add and connect**를 누르면 서버에 연결해 도구 목록을 가져옵니다. 도구마다 read-only / writes / destructive 표시가 붙습니다. 서버의 도구가 바뀌면 **Refresh tools**를 누르세요.

에이전트가 쓰고 있는 서버는 삭제할 수 없습니다. 먼저 Agent Settings에서 그 서버의 도구를 해제하세요.

### 채팅에서 승인하기

Ask first 도구를 호출하면 에이전트는 실행 직전에 멈추고, 답변 자리에 **Approval needed** 카드가 뜹니다.

- **Approve**: 표시된 인자 그대로 실행하고 이어서 답변합니다.
- **Edit arguments**: 인자를 JSON으로 고친 뒤 **Approve with changes**로 실행합니다. 모델이 ID를 잘못 넣었을 때 쓰세요.
- **Reject**: 실행하지 않고, 에이전트가 "실행하지 않았다"고 답합니다.

승인 대기 중에는 새 메시지를 보낼 수 없습니다. 대화를 닫았다가 다시 열어도 카드가 그대로 남아 있습니다. 질문을 수정하면 대기 중이던 승인은 만료됩니다.

Ask first 도구는 멈췄다가 이어서 실행할 수 있는 채팅 세션에서만 쓰입니다. 세션 없는 채팅 API, 평가 실행, 다른 에이전트의 위임으로 실행될 때는 그 도구가 빠집니다.

### 호출 기록

MCP Servers 화면 아래의 **Recent tool calls**에 모든 호출이 남습니다. 자동 실행(auto), 대기(pending), 승인(approved), 거절(rejected), 만료(expired) 상태와 승인한 사람, 인자(수정된 경우 표시), 결과를 볼 수 있습니다.

### 데모 서버

`server/demo/maintenance_mcp.py`는 공장 설비 정비 데스크를 흉내 낸 mock 서버입니다. 설비 상태·경보 조회, 정비 기사 조회, 작업지시 생성·배정·완료 도구가 있고, http://localhost:8765/ 에서 작업지시가 바뀌는 모습을 볼 수 있습니다.

```bash
cd server && MCP_TOKEN_MAINTENANCE=demo-maintenance-token uv run python -m demo.maintenance_mcp
```

## 9. Retrieval Lab

검색 품질을 실험하는 곳으로, 세 개의 탭으로 구성됩니다.

### Search

자연어 질의로 현재 워크스페이스를 검색합니다.

| 필드 | 설명 |
| ---- | ---- |
| Query | 검색할 내용 (필수) |
| Top K | 반환할 최대 결과 수 (기본 5, 최대 50) |
| Document ID | 특정 문서 안에서만 검색할 때 (선택) |
| Document sets | 고른 세트 안에서만 검색합니다. 에이전트에 같은 세트를 지정했을 때와 같은 범위입니다. 하나도 고르지 않으면 워크스페이스 전체를 검색합니다(실험용). |
| Pipeline | 검색에 쓸 파이프라인 (선택) |

### Pipelines

검색 단계(임베딩 → 벡터 검색 → 리랭크 등)를 노드로 조립합니다. active 상태인 파이프라인은 Agent Settings에서 에이전트의 검색 파이프라인으로 지정할 수 있습니다.

### Chunking *(워크스페이스 admin)*

파일을 실제로 업로드하지 않고 청킹 결과를 미리 확인합니다.

1. 파일을 선택합니다.
2. 청킹 전략과 파라미터를 설정합니다.
3. **Preview Chunks**를 누르면 분할된 청크와 각 청크의 문자 수·메타데이터가 표시됩니다.
4. **Markdown** 탭에서 원본 텍스트 추출 결과를 확인할 수 있습니다.

## 10. Evaluate *(워크스페이스 admin)*

현재 에이전트에 질문 세트를 돌려 설정 변경의 효과를 수치로 비교합니다.

- 문항마다 질문, 정답 문서(선택), 답변에 들어가야 할 핵심어(선택)를 입력합니다. 👎 받은 질문을 그대로 가져올 수도 있습니다.
- 실행 시 프롬프트와 설정(모델, 파이프라인 등)을 바꿔 A/B로 비교할 수 있습니다.
- 지표: 문서 적중률(hit), MRR, 답변 핵심어 포함률, 근거성(LLM 채점, 1–5), 지연, 토큰.

## 11. Members · Users · Workspaces

### Members *(워크스페이스 admin)*

현재 워크스페이스의 멤버를 관리합니다. 상단 폼에서 유저와 역할을 고르고 **Add Member**를 누르세요. 역할 드롭다운을 바꾸면 즉시 반영되고, **Remove**로 제거합니다.

| 역할 | 권한 |
| ---- | ---- |
| `admin` | 문서·문서 세트 쓰기, 에이전트 설정·생성·삭제, 평가, 멤버 관리 |
| `member` | 문서·문서 세트 쓰기, 채팅 |
| `viewer` | 문서 열람, 검색, 채팅 |

### Users *(superadmin)*

계정을 만들고 목록을 확인합니다.

### Workspaces *(superadmin)*

워크스페이스를 만들고 삭제합니다. 워크스페이스를 만들면 같은 이름의 기본 에이전트가 함께 생성됩니다.

## 12. 문서 상태 설명

| 상태 | 의미 |
| ---- | ---- |
| `pending` | 파일 저장 완료, 인덱싱 대기 중 |
| `chunking` | 텍스트를 청크로 분할 중 |
| `embedding` | 임베딩(벡터 변환) 처리 중 |
| `indexed` | 인덱싱 완료, 검색 가능 |
| `failed` | 인덱싱 실패 (상세 페이지에서 오류 메시지 확인 가능) |

---

## 13. 지원 파일 형식

| 형식 | 확장자 |
| ---- | ------ |
| PDF | `.pdf` |
| Word | `.docx`, `.doc` |
| PowerPoint | `.pptx`, `.ppt` |
| Excel | `.xlsx`, `.xls` |
| 텍스트 | `.txt`, `.md`, `.markdown`, `.rst`, `.log` |

위 형식 외의 파일은 텍스트로 읽기를 시도하며, 읽을 수 없는 경우 업로드가 실패합니다.
